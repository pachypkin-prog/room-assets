# Часто задаваемые вопросы (FAQ)

## 🚀 Запуск и инсталляция

### В: Какие требования для запуска?
**О:** 
- Node.js 18+ ([nodejs.org](https://nodejs.org))
- npm (идёт в комплекте с Node)
- Современный браузер (Chrome, Firefox, Safari, Edge)

### В: Как быстро начать?
**О:**
```bash
git clone <repo>
cd room-assets
npm install
npm run dev
```
Откройте http://localhost:5173

Подробнее: см. [QUICKSTART.md](QUICKSTART.md)

### В: Что делать если npm install не работает?
**О:**
```bash
# Очистить cache
npm cache clean --force

# Удалить package-lock.json и node_modules
rm -rf node_modules package-lock.json

# Установить заново
npm install
```

### В: Какая версия Node рекомендуется?
**О:** 
- Минимум: 18.0.0
- Рекомендуется: 20.10+
- Проверка: `node --version`

### В: Нужен ли Docker?
**О:** Нет, опционально. Для production можно использовать, но для разработки не требуется.

## 💾 Данные и хранилище

### В: Где хранятся данные?
**О:** В браузере, в IndexedDB (встроенной базе данных браузера). Не на сервере.

### В: Могу ли я синхронизировать данные между компьютерами?
**О:** Только через экспорт/импорт JSON:
1. Экспортируйте на компьютере A
2. Отправьте файл на компьютере B
3. Импортируйте файл на B

Для синхронизации в реальном времени нужен backend API.

### В: Что будет если очистить браузер history?
**О:** 
- ✅ Данные IndexedDB сохранятся (это не cookies)
- ✓ Приложение будет работать

### В: Безопасны ли мои данные?
**О:**
- ✅ Локальное хранилище (не на интернете)
- ✅ Никто не может访问 (кроме вас)
- ⚠️ Если удалить IndexedDB → данные потеряются
- ✅ Регулярно экспортируйте резервные копии!

### В: Могу ли я экспортировать данные в Excel?
**О:** 
Пока нет (Excel импорт планируется для v2.0). 

**Временное решение:**
1. Экспортируйте JSON
2. Откройте в Google Sheets
3. Paste raw JSON → Sheets парсит таблицу

Или используйте конвертор JSON→CSV→Excel.

### В: Какой максимум данных можно сохранить?
**О:** 
- IndexedDB лимит: ~50-100 MB (зависит от браузера)
- Для приложения достаточно для ~100,000 бронирований
- После этого нужен backend с БД (PostgreSQL)

## 🔐 Безопасность и приватность

### В: Отправляются ли данные на сервер?
**О:** Нет! Приложение работает полностью локально. Данные никогда не отправляются куда-либо.

### В: Может ли кто-то хакировать мои данные?
**О:**
- IndexedDB защищена браузером (не доступна другим сайтам)
- Если кто-то украдёт ваш компьютер → может получить доступ
- **Решение:** Используйте пароль на компьютер / шифрование диска

### В: Нужны ли мне права администратора для установки?
**О:** Нет, это веб-приложение (не нужна установка).

### В: Может ли приложение украсть мои пароли?
**О:** Нет, приложение полностью клиентское (открытый код). 
- Смотрите исходный код: `/src/App.tsx`
- Нет отправок данных на сервер
- Нет скрытых запросов

### В: Как часто вы обновляете безопасность?
**О:** Приложение использует только стандартные браузерные API. Обновления идут когда:
- Выходит новая версия React (автоматическое обновление)
- Находятся новые vulnerabilities (исправляются в новых версиях)

## 🎯 Функциональность

### В: Могу ли я удалять комнаты?
**О:** Пока нет (v1.0 MVP не включает). Планируется для v1.1.

**Временное решение:** Очистите все бронирования комнаты, и она перестанет отображаться в реальных сценариях.

### В: Могу ли я установить пароль на приложение?
**О:** Нет встроенной аутентификации (v1.0). 

**Решение для защиты:**
- Используйте HTTP Basic Auth на сервере (при развёртывании)
- Или используйте браузерный пароль на компьютер

### В: Как установить уведомления о бронированиях?
**О:** Планируется для v2.0. 

**Временное решение:**
- Установите Google Calendar синхронизацию
- Или используйте простой calendar напоминания

### В: Могу ли я просмотреть статистику использования?
**О:** Нет встроенной статистики (v1.0).

**Что скоро:**
- Количество бронирований в день
- Самые популярные комнаты
- Загрузка ресурсов

### В: Может ли несколько человек работать одновременно?
**О:** Нет синхронизации в реальном времени (v1.0).

**Решение:**
1. Поделитесь экраном (Zoom, Teams)
2. Или экспортируйте/импортируйте данные между пользователями
3. Планируется для v2.0 с backend синхронизацией

### В: Как работает поиск?
**О:** 
- Ищет в названии комнаты/актива
- Ищет в описании функций
- Регистронезависимый поиск
- Ищет по названию бронирования

Примеры:
- "Conference" → все комнаты с "Conference"
- "Projector" → все проекторы
- "Team Meeting" → бронирование с этим названием

### В: Почему появляется ошибка "Time overlaps"?
**О:** Системе найдена ошибка пересечения времени:
```
Существующее бронирование:  10:00 - 11:00
Ваше бронирование:          10:30 - 11:30
                             ^^^^^ пересечение!
```

**Решение:** Выберите другое время, которое не пересекается.

### В: Приложение работает на мобильном?
**О:** Да! Полностью responsive дизайн.

**Поддерживаемые браузеры:**
- iOS Safari 11+
- Chrome Mobile 60+
- Firefox Mobile 55+

### В: Почему дата/время отображается неправильно?
**О:** Приложение использует локальную временную зону вашего браузера.

**Проверка:**
1. Settings → Time & date
2. Убедиться что timezone установлена правильно
3. Если неправильно → изменить и перезагрузить приложение

## 🛠️ Разработка и кастомизация

### В: Как добавить новую функцию?
**О:** См. [CONTRIBUTING.md](CONTRIBUTING.md) → раздел "Добавление нового функционала"

Примеры:
- Добавить фильтр по дате
- Добавить тёмную тему
- Добавить экспорт в CSV

### В: Где найти исходный код?
**О:** Основной код в одном файле:
- `src/App.tsx` - компоненты, логика, утилиты (550+ строк)
- `src/App.css` - все стили (450+ строк)

### В: Как изменить цвета?
**О:** 
Откройте `src/App.css` и найдите CSS переменные:

```css
:root {
  --primary-color: #3f51b5;      /* Изменить сюда */
  --success-color: #4caf50;
  --danger-color: #f44336;
}
```

### В: Могу ли я использовать приложение для другой целиAssistant?
**О:** Да! Приложение легко адаптируется:

**Примеры:**
1. Аренда автомобилей (вместо комнат → автомобили)
2. Бронирование оборудования (вместо активов → оборудование)
3. Расписание мероприятий (вместо бронирований → события)

Просто измените названия в коде и данные.

### В: Как добавить новое поле в бронирование?
**О:**
1. Обновить интерфейс `Booking` в `App.tsx`:
   ```typescript
   interface Booking {
     // ... существующие поля
     department?: string;  // новое поле
   }
   ```

2. Добавить input в BookingForm
3. Обновить валидацию если нужно

### В: Как добавить разные роли (админ, пользователь)?
**О:** Нужна аутентификация (v2.0+).

**Временное решение:** Используйте HTTP Basic Auth на сервере при развёртывании.

## 🚀 Развёртывание

### В: Как развернуть приложение в интернет?
**О:** Несколько вариантов (с простого на сложный):

1. **GitHub Pages** (бесплатно, 5 минут)
   - Наиболее легко
   - Смотрите [DEPLOYMENT.md](DEPLOYMENT.md) → GitHub Pages

2. **Vercel** (бесплатно, рекомендуется)
   - Лучшая производительность
   - Автоматический deploy из Git

3. **Netlify** (бесплатно)
   - Похоже на Vercel
   - Хорошая поддержка

4. **Собственный сервер** (платно)
   - Полный контроль
   - Сложнее настраивать

### В: Сколько стоит развёртывание?
**О:**
- GitHub Pages: **бесплатно** ✅
- Vercel: **бесплатно** (есть платные планы)
- Netlify: **бесплатно** (есть платные планы)
- AWS S3: **~0.5-1$** в месяц (очень дёшево)
- VPS сервер: **5-20$** в месяц

Для MVP рекомендуем Vercel (бесплатно + лучше всех).

### В: Нужен ли мне собственный домен?
**О:** Нет, можно использовать бесплатный:
- `yourusername.github.io`
- `projectname.vercel.app`
- `projectname.netlify.app`

Собственный домен (yourcompany.com) стоит ~10-15$ в год.

### В: Как получить SSL сертификат?
**О:**
- Vercel/Netlify: Автоматический (бесплатно)
- GitHub Pages: Автоматический (бесплатно)
- Собственный сервер: Let's Encrypt (бесплатно)

Смотрите [DEPLOYMENT.md](DEPLOYMENT.md) → SSL сертификат.

### В: Может ли приложение работать offline?
**О:** Да, частично! 

**Что работает offline:**
- Просмотр существующих бронирований
- Создание новых бронирований (сохранятся локально)
- Поиск и фильтрация

**Что не работает:**
- Импорт новых данных
- Синхронизация с другими устройствами

Для полного offline режима нужен Service Worker (планируется v2.0).

## 📊 Производительность

### В: Почему приложение медленное?
**О:** Если вы заметили задержки:

**О:** Отчитайте issue с:
- Сколько данных (rooms, assets, bookings)
- Какой браузер и версия

## 💡 Советы и трюки

### В: Как создать резервную копию?
**О:**
```
Вкладка Bookings → Кнопка Export
↓
Сохранится файл room-assets-backup-YYYY-MM-DD.json
↓
Отправьте на Google Drive или Dropbox
```

### В: Как восстановить из резервной копии?
**О:**
```
Вкладка Bookings → Кнопка Import
↓
Выберите backup файл
↓
Данные загружаются в IndexedDB
```

### В: Как просмотреть все бронирования на неделю?
**О:** Пока нет встроенного календаря (v2.0).

**Решение:** Смотрите таблицу Bookings и фильтруйте по датам (Ctrl+F в браузере).

### В: Как экспортировать только определённые бронирования?
**О:** Пока нет селективного экспорта (v2.0).

**Решение:** Экспортируйте всё → отредактируйте JSON вручную.

### В: Как установить напоминание перед бронированием?
**О:**
1. Синхронизируйте с Google Calendar (v2.0)
2. Или установите напоминание в календаре браузера

### В: Как поделиться бронированием с коллегой?
**О:**
1. Экспортируйте данные
2. Отправьте JSON файл
3. Коллега импортирует

Или просто скопируйте/вставьте ссылку для совместного просмотра.
